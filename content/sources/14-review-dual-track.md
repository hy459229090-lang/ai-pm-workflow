# 第 14 篇：Review 双轨 — 规范性检查和内容判断分开

> 一句话：第 07 篇讲"三道检查点"，这篇讲"谁来审"——把结构规范性和内容质量分开，两个关卡各管一摊，不打架。

---

## 一份被"审糊"的 PRD

毛球 App 的宠物美容预约功能，PRD 写完了。我按第 07 篇的方法，让 AI 先自审一遍。

结果 AI 的自审意见是这样的：

```
问题 1：预约状态机的异常流程不够细（高）
问题 2："到店核销"这个交互对用户不够友好（中）
问题 3：标题层级不规范，格式要调整（低）
```

三行意见，三个完全不同的维度：一个是**技术结构**，一个是**用户内容**，一个是**格式规范**。

我盯着这三行，不知道先改哪个。更麻烦的是——**问题 2 是内容判断（体验好不好），问题 1 是技术判断（状态机对不对），问题 3 是规范判断（格式符不符合）。这三个应该由不同的"人"来审，而不是混在同一个 Agent 的脑子里。**

因为：
- 让写格式规范的人判断"交互好不好"——它没有用户视角，瞎说
- 让看内容的人判断"状态机对不对"——它没有技术视角，乱评
- 让审状态机的人挑"标题层级"——它根本不关注这个

**一个评审 Agent 同时干三件事，结果就是三件事都干不好。**

---

## Review 双轨：拆成两关

Review 双轨的核心：**把评审拆成两条独立的线，各管一摊。**

| 轨道 | 审什么 | 本质 | 谁说了算 |
|------|--------|------|----------|
| **规范性检查** | 结构完整 / 边界定义 / 口径来源 / 命名规范 / 格式 | "文档该有的都有了" | 检查者给出结论 |
| **内容/策略评审** | 文案戳不戳用户 / 策略合不合理 / 数据支不支持 / 推荐时机 | "内容质量行不行" | 意见是建议，产品拍板 |

两条线分开跑，不混在一个 Agent 里。

---

## 轨道 1：规范性检查 — 强制关卡

这一关回答的问题是：**"这份文档结构上完整吗？能过吗？"**

只做规范性检查，**不做内容判断**。内容对错是另一条线的事。

毛球宠物美容预约 PRD 的规范性检查长这样：

```markdown
## 检查结果
产出物：docs/prd/宠物美容预约/宠物美容预约_PRD.md
类型：PRD

检查项统计：10 项 / 通过 8 / 待确认 1 / 不通过 1

✅ 通过：
- 目标、用户场景、方案、埋点、排期各章节齐全
- 命名符合规范（项目_类型.md）
- 大文件有章节速览

⚠️ 待确认：
- "预约冲突"边界：写了"冲突提示改选时间"，但没写提示的具体交互形式

❌ 不通过：
- 验收标准缺失：每个需求没有可验证的通过条件

建议操作：修改后再看（补齐验收标准 + 明确冲突提示交互）
```

**关键规则**：
- 只审结构规范，不评内容好坏
- 结论必须明确：通过 / 修改后再看 / 不通过
- 目标：让产品经理 3 分钟内判断要不要处理

**它是强制关卡**——所有产出交给 PM 之前，先过这一关。

---

## 轨道 2：内容/策略评审 — 运营顾问

这一关回答的问题是：**"这份内容/策略真的行吗？"**

审的是文案、活动策略、推荐时机、数据支撑——这些"内容质量"层面的东西。

毛球的例子：宠物美容预约要写一个功能入口的文案。内容评审的意见：

```markdown
## 内容评审
核心判断：现文案"预约宠物美容，便捷到店"不戳用户。

问题清单：
1. 痛点没戳中——用户真正怕的是"节假日约不上"，文案没提
2. 价值不清——"便捷"太虚，不如"线上预约免排队"
3. 推荐时机——美容预约功能上线时，正好是换毛季，可借势

修改建议：
"换毛季到了，线上预约宠物美容，到店免排队"
```

**关键规则**：
- 意见是**建议**，产品拍板——不替 PM 做最终决策
- 不写需求文档、不做技术可行性判断（那是其他角色的活）
- 只从内容/策略角度给专业意见

**它不是门禁**——是运营顾问。听不听由你。

---

## 为什么必须分开

把两个轨道拆开，有三个实打实的好处：

### 1. 各审各的，不打架

规范性检查说"验收标准缺失"，内容评审说"文案不戳用户"——两条意见可以并行处理，不用纠结哪个优先。**一个管结构，一个管内容，互不干扰。**

### 2. 不会互相带偏

如果混在一个 Agent 里，规范性检查会说"结构完整了，通过"，但内容烂得一批——因为那个 Agent 没有内容判断能力。分开后，**每个轨道只用它擅长的能力审它该审的维度。**

### 3. 分工可演化

规范性检查可以做成自动的、强制的、每次必跑；内容评审则按需触发（有文案/活动策略才跑）。**两条线生命周期不同，拆开才好独立演进。**

---

## 双轨和 07 篇的关系

第 07 篇讲的是**什么时候看、看什么**（入口检查 → 结构检查 → 细节抽查）。

这一篇讲的是**谁来审、审哪个维度**（规范性 vs 内容）。

两者配合：
- 07 篇：审的节奏和重点
- 本篇：审的分工和轨道

**综合起来**：任何产出交给 PM 前，过规范性检查（强制关卡）；有内容/策略的部分，再加一道内容评审（运营顾问）。两道关都过了，产出才到 PM 手上。

---

## 效果对比

| 指标 | 单轨评审（07 篇） | 双轨评审（本篇） |
|------|-----------------|-----------------|
| 审的维度 | 混在一起 | 结构规范性 / 内容策略分两条线 |
| 规范性 | 有 | 强制关卡，3 分钟判断 |
| 内容/策略 | 靠运气 | 运营顾问按需触发 |
| PM 的判断成本 | 读一堆混合意见 | 各轨道结论清晰 |
| 轨道演化 | 绑死 | 独立演进 |

## 自查清单

- [ ] 规范性检查是独立关卡，只审结构/边界/命名/格式，不评内容
- [ ] 规范性检查结论明确（通过/修改后再看/不通过），PM 3 分钟能判断
- [ ] 内容/策略评审独立，意见是建议、产品拍板
- [ ] 涉及文案/活动策略时，内容评审按需触发
- [ ] 真实跑过一次：确认两条轨道没互相带偏
