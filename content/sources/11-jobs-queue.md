# 第 11 篇：工作队列 — 让任务不丢、不卡、可追

> 一句话：任务一多就会乱。把每个任务写成一个"卡片"，编号、留痕、追进度——这是多 Agent 协作的地基。

---

## 当任务开始排队

毛球 App 同时推进四件事：

- 推荐 feed 改版（PRD → 技术方案 → 埋点 → 测试）
- 宠物健康问答上线
- 附近服务的商家入驻流程
- 运营活动体系搭建

再加上日常的取数、汇报、竞品调研……我把任务"外包"给 Agent 之后，遇到一个新问题：

**任务一多，就不知道进行到哪了。**

- "推荐 feed 改版到哪一步了？"——翻聊天记录，找不到了
- "宠物问答的埋点方案谁在写？"——没人记得
- "商家入驻有个阻塞，等谁决策？"——忘了，卡了一周

这就是多 Agent 协作必须面对的问题：**你自己只有一个大脑，但任务有十几个、Agent 有十几个。** 不靠脑子记，靠一个系统记。

---

## 工作队列是什么

工作队列（Job Queue / JOBS）是**任务的持久化卡片系统**。

每个任务一张卡片，写清楚：
- 要交付什么
- 拆成几步
- 现在到哪了
- 下一步做什么
- 有没有卡住

所有卡片放在一个文件里，AI 和你都能看、能更新。

**它不是任务清单（todo list），是任务的"病历本"**——不仅记录要做的事，还记录每一步的状态、阻塞、决策、产出。

---

## 为什么需要它：三个场景

### 场景 1：任务多，记不住

毛球同时 4 个项目 + 十几张卡片。没有队列，任务会丢。

### 场景 2：AI 一执行就"失忆"

AI 每轮对话都重新开始。上周给 Agent 派的任务，这周开新对话，它不记得了。**队列文件是跨对话的记忆载体。**

### 场景 3：阻塞没人管

"商家入驻的审核流程没定，等 PM 决策"——如果这句话只出现在一次对话里，就消失了。写在队列里，每次开工 AI 都会看到"这里卡着，等谁决策"。

---

## 实操：卡片五字段 + 生命周期

### 卡片长什么样

每张任务卡片 5 个固定字段：

```markdown
## B01 — 推荐 feed 改版

**目标**：完成推荐 feed 改版的 PRD + 技术方案 + 埋点方案 + 测试用例，产出到 docs/prd/推荐系统/

**步骤清单**：
- [x] 写推荐策略 PRD（已评审通过）
- [x] 技术方案：召回模型 + AB 框架
- [ ] 埋点方案（曝光/点击/停留/负反馈）
- [ ] 测试用例

**当前进度**：技术方案完成，埋点方案进行中。遗留：负反馈事件定义待确认。

**下一步**：① 和运营确认负反馈口径 ② 写埋点方案初稿

**阻塞项**：无（如需写：阻塞原因 + 需要谁决策 + 解除条件）
```

字段含义：
- **目标**：交付什么 + 产出到哪
- **步骤清单**：拆好的步骤，`[x]` 勾选
- **当前进度**：状态 + 已完成证据 + 遗留问题
- **下一步**：具体行动项
- **阻塞项**：卡在哪、等谁、怎么解除

### 生命周期

任务卡片有标准的状态流转：

```
idea（想法）→ plan_ready（计划提交待审批）→ in_progress（审批通过，执行中）
→ review_ready（产出已评审，待拍板）→ done（完成）
```

两个强制关卡：
- **plan_ready → in_progress**：要过"审批"——把计划给人看，人点头才开始
- **in_progress → review_ready**：产出要过"评审"——质量关卡（第 07 篇）

这两个关卡，正是三条核心理念里"人必须守住的关卡"（审批计划、Review 产出）。

## 关键机制：任务持久化的门槛

这是我踩坑后总结的最重要一条：

**步骤超过 5 个的任务，开工前必须先建任务卡片。**

原因：步骤越多，越容易在执行中途丢上下文、忘依赖、卡住没人发现。先写卡片，等于先立"契约"——你和 AI 都知道要做什么、做到哪了。

```markdown
## 任务持久化规则
- 步骤 ≥5 的任务，执行前必须先在队列文件建一张卡片（含：目标、步骤清单、当前进度、下一步、阻塞项）
- 建完卡片必须先告知 PM（卡片编号 + 目标 + 步骤概要），PM 确认后才开始执行
- 每完成一步更新卡片进度；遇到阻塞立即记录
```

**这条规则让"外包出去的活"始终在视野内。**

## 多项目怎么办：编号前缀避撞

毛球同时有产品需求（P）、工具转 Skill（T）、运营活动（B）、评测（M）多类任务。

如果所有任务都用 01、02 编号，跨项目会撞号。解法：**每类任务用独立前缀**。

| 前缀 | 类型 |
|------|------|
| P01、P02 | 产品需求 |
| T01 | 工具转 Skill |
| B01 | 运营活动 |
| M01 | 评测 |

每个项目一个队列文件（如 `JOBS-产品需求.md`、`JOBS-运营.md`），文件内按前缀编号。

---

## 效果对比

| 指标 | 没有队列 | 有队列 |
|------|---------|--------|
| "到哪一步了？" | 翻聊天记录 | 看卡片当前进度 |
| 新对话的 AI | 失忆 | 读队列文件，接上 |
| 阻塞项 | 消失一周 | 每次开工可见 |
| 5+ 步任务 | 中途丢上下文 | 卡片驱动，步步入账 |
| 多项目并行 | 编号混乱 | 前缀隔离 |

---

## 自查清单

- [ ] 有队列文件（JOBS 体系），任务卡片含五字段
- [ ] 步骤 ≥5 的任务开工前先建卡片，且先告知 PM
- [ ] 卡片有生命周期流转，plan_ready 过审批、review_ready 过评审
- [ ] 多类任务用独立编号前缀
- [ ] 每完成一步更新卡片，阻塞立即记录
- [ ] AI 跨对话能通过读队列文件接上进度
