# 可以一起做些什么

[← 回到个人介绍](../README.md)

我在腾讯做过社区互动、增长与商业化，目前在网易做 C 端 AI 助手。与此同时，我也给自己搭产研工具：让资料、任务、执行和检查能接上，而不是每次从头准备。

## 业务判断和动手验证，放在一起做

讨论一个想法，先看它服务谁、改变什么行为、怎么衡量结果。再核对现有实现和成本，能用原型或接口检查的问题，不等到最后才发现。

这类合作适合：想法很多但优先级不清楚，或者已经有方案，需要把实现约束和验证办法补齐。

## 不只写提示词，也维护工作系统

资料的当前版本、任务的输入输出、工具权限与检查标准，需要一起考虑。重复任务可以沉淀成可复用的能力，关键判断和交付仍由人负责。

这类合作适合：已经开始使用 AI，但上下文总要重讲，任务经常断在不同工具之间，希望从一个真实任务开始改善。

## 不只看答案，也检查怎么答出来

从整段对话回看用户意图、检索内容和工具返回，判断问题发生在哪一步。机器评估需要人工校准，修订后继续回归，不能把答案更长或工具调用成功当作用户任务完成。

这类合作适合：助手看起来能聊，但真实用户的错误反复出现，需要评估、归因和修改优先级。

## 公开边界

这里只介绍跨任务归纳的做法，不表示每个项目都跑过全部步骤。设计稿不等于运行原型，接口检查不等于端到端验收，个人探索不等于已发布产品。这里不展示业务数据、内部案例、具体架构或未公开项目。

公司名称仅用于说明职业经历，合作交流不代表公司授权或背书。
